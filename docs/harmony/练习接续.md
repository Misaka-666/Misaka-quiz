# 鸿蒙练习接续

更新：2026-11-18。版本：0.9.11-harmony / 21。

## 使用范围

- 只接续当前练习。不提供云同步，也不接续计时考试。
- 携带题号、题目顺序、答案、未提交输入、批量状态、乱序种子和背题模式。
- 携带当前练习所需的完整题库及图片。跨题库练习会带上多个题库。
- 不迁移 AI 密钥、设备偏好、正在生成的 AI 内容或无关学习历史。
- 接收端原有练习放入“练习 → 暂存练习”。可随时切回。
- 接续完成后，源端返回首页，原练习标为“已接续”并暂存。再次在源端作答时建立独立分支，不替另一端结算。

两台原生鸿蒙设备需安装兼容版本，并登录同一华为账号。按系统要求开启 WLAN、蓝牙和“多设备协同 → 接续”。在源端打开练习页，再通过另一台设备的系统接续入口继续。入口位置以设备系统为准。

官方说明：

- [应用接续](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-continue-cast)
- [接续数据迁移](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-continue-data)

## 数据规则

- 接收完全部文件并校验后，才替换当前练习。题库、错题状态、当前练习和暂存列表一起原子保存。
- 保存失败、取消、超时或接收期间本机数据发生变化时，不覆盖原数据。
- 同标识且内容一致的题库复用。内容不同则生成独立题库标识，并重映射练习和判题记录中的引用。
- 同一练习同一修订的重复包不新增副本。本机存在不同进度时保留分支。已在本机完成的练习不再次接收。
- 只携带当前练习涉及题目的错题状态。累计次数取最大值，避免重复相加；任一端仍未掌握时保留复习需求。这不是两端全部学习历史的合并。
- 暂存练习写入本机 `state.json`。现有跨平台 ZIP 备份格式保持不变，不新增练习现场字段。

## 实现约定

- `EntryAbility` 启用 `continuable` 和单实例启动。`onCreate/onNewWant` 识别接续，窗口恢复复用设置初始化。系统页面栈恢复关闭，由应用进入接收页，再进入练习。
- `PracticeContinuation.ets` 管理系统数据对象、接收页状态、60 秒超时和保存回执。系统传输完成不等于业务保存成功；收到落盘回执后才将源端练习暂存。
- `ContinuationCodec.ts` 管理版本、校验、题库重映射和分支保留。`PracticeSessionCore` 增加会话标识、修订标识和当前练习的背题/乱序设置，兼容旧本地存档。
- `ContinuationFiles.ets` 生成一个 `.mqp` 文件资产。内容为四字节大端清单长度、UTF-8 JSON 清单和顺序图片字节。系统 Want 只带协议版本和分布式会话标识。
- 清单最多 20MB，单图最多 20MB，最多 999 张去重图片，整个文件最多 100MB。图片按 SHA-256 去重和校验。文件读取、写入和摘要使用异步接口。
- 图片完整校验后写入 `question_assets/continuation/<摘要>`，再原子提交状态。源设备的绝对路径不能直接使用。失败后已校验的图片可能仍留在该缓存目录，可供重试复用。
- `.mqp` 仅服务鸿蒙接续，不替代跨平台备份。不新增第三方依赖。

## 验证与限制

已执行：

- 原七项 Node 自检与新增 `continuation` 自检。包含协议拒绝、旧存档、图片损坏、题库冲突、引用重映射、重复接收、分支保留、完成后拒收、保存失败回滚、超时重试及取消后的过期回调。
- 平台文件接口的 Node 替身运行实际文件编解码；生命周期使用可控数据对象替身。这些检查不证明系统网络传输可用。
- 鸿蒙构建。仍有平台能力提示、异常处理提示和既有弃用接口警告。构建产物未签名。
- WideFoldM4：旧练习恢复，暂存列表显示，切换到第 2 题，原练习仍保留，强制停止后两场练习恢复。模拟器测试存档已恢复，前后 SHA-256 一致。

未执行：

- 双真机系统入口、真实数据对象回执、图片资产落地，以及两设备冷启动/热启动接续。
- 真实断网、存储耗尽、设备后台限制和同应用身份签名验证。
- 含图大题库的传输耗时、峰值内存和真机界面响应测量。100MB 是输入上限，不是性能承诺。

模拟器不支持系统接续。真机验收时，两端使用兼容签名安装包；先测无图小题库，再测实际题库和含图大题库。分别记录文件体积、打包耗时、系统传输耗时和恢复耗时。检查失败后原练习可继续，成功后源端不再保持可直接作答的原会话。验收通过前，不将功能标为真机可用。
