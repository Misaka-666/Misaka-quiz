# M6 上篇：备份协议与导出

文档版本：1.0 · 与 M6 下篇共同交付 0.7.0-harmony · [返回索引](README.md)

## 1. 目标与现有基础

复用 Models.ts 中 `*ToJson(registerAsset)` 及 M0 ZlibSpike；不自建压缩库。外部备份格式以 Android 的实际导出/导入实现为准，不能把鸿蒙内部 state.json 直接当公共协议。

查阅 Android `state/QuizRepository.kt` 中 buildBackup/export/import 相关函数，以及 `apps/web/app.js` 中的导入导出逻辑。M0 已验证 ZIP 能被标准 unzip 读取，这只是容器验证，不代表三端业务字段互通已完成。

## 2. 协议冻结流程

1. 从 Android、Web 各生成一份脱敏真实备份；记录版本、生成步骤、文件哈希及内容说明。
2. 列出根字段：格式标识、版本字段（若已有）、题库、活动题库、错题、收藏、斩题、记录、顺序进度、设置。
3. 对每个字段记录类型、缺失默认值、null/省略规则、导出来源、导入写回位置。
4. 明确全量与选择题库导出的范围；历史记录跨多库时采用 Android 兼容规则，必要时记录无法无损选择导出的差异。
5. 明确设置是否包含在现有全量协议内；若不包含，UI 说明范围，不擅自声称备份全部偏好。
6. 密钥、鉴权头、临时文件与会话网络状态不进入备份。外部协议的扩展须验证旧端容忍性。

字段映射表在实施时保存为独立 Markdown 附录；表中不能以推测值替代实际样本与源码。

## 3. 导出处理流程

用户选择范围 → 获取一致的数据快照 → 序列化并注册资产 → 构建临时产物 → 校验 → 用户选择目标 → 完成写入 → 报告成功/失败 → 清理临时文件。

### 3.1 JSON 核心

- 拟新增 `.ts` 纯函数承载 buildBackupJson 及选择性过滤，平台文件操作保留在 Repository 或少量 `.ets` 辅助代码。
- kind 使用已确认的 `misaka_quiz_full_backup`；其余字段严格依据映射表。
- 只导出稳定快照，避免序列化期间用户操作造成计数与内容不一致。
- 图片注册同时遍历题库、错题、收藏、记录内嵌快照，不能只遍历当前题库。
- 同一资产复用同一相对路径；重名不同内容不能覆盖。

### 3.2 ZIP 平台层

1. 创建本次导出专属临时目录，写入 `backup.json`。
2. 仅复制实际引用图片到 `question_assets/`，不要复制整个私人数据目录。
3. 资产目标路径必须是安全相对路径，禁止绝对路径、盘符、`..` 逃逸。
4. 根据 ZlibSpike 的已验证参数压缩，确认 ZIP 根部就是 backup.json，而非额外嵌套目录。
5. 临时 ZIP 先验证可读与关键条目，再保存到用户选定位置。
6. picker 取消是取消，不显示失败；写入异常不能显示成功路径。
7. 结束后只清理本次临时目录；失败信息包含阶段与可重试操作，不泄露密钥。

### 3.3 独立 JSON 导出

必须明确图片承载方式。若对端支持内嵌 data URI，可按已验证格式内嵌；否则明确纯 JSON 不携带图片并优先推荐 ZIP。禁止输出设备绝对路径后声称 JSON 可完整迁移图片。

## 4. UI 与失败行为

数据管理 → 全量备份/选择题库 → 格式与范围说明 → 保存。导出中防重复点击；成功后展示可理解的文件名或目标信息。缺失图片默认中止完整备份并列出问题；如允许跳过，必须显式选择并在结果中标注不完整。
