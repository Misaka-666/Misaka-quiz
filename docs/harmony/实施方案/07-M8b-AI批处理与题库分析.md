# M8b：AI 核对、补解析与题库分析

文档版本：1.0 · M8 最终目标：0.9.0-harmony · [返回索引](README.md)

## 1. 前置与范围

M8a 的流解析、取消、任务隔离、缓存和错误展示通过验收后，再实现批处理。复用同一客户端和提示词，不复制流解析到各页面。

交付：导入核对、无解析题补全、题库分析、知识点聚合、文本导出、缓存与重试。知识点图谱首版可以采用分组列表表达关系；若图形展示是既定必需功能，再单独补 UI，不引入无必要图布局依赖。

## 2. 批处理最小执行流程

选择范围 → 冻结题目快照 → 校验题量/字符限制 → 顺序分批发送 → 每批校验结果 → 保存候选结果与进度 → 用户确认 → 检查题目版本 → 应用 → 持久化。

默认串行批次，先保证限额与隔离；只有测量证明需要时再加有限并发。每个题库使用独立任务 ID、进度和结果，避免多库流式内容混写。

计数区分待处理、成功、失败、跳过、待确认、已应用。进度百分比不能只按收到字符数计算。

## 3. AI 核对导入

1. 在导入预览中调用，对候选题目工作，不直接修改正式题库。
2. 展示异常类别、原值、建议值和说明；aiOnlyAnomaly 仅影响展示，不丢弃原始题目。
3. aiRequireConfirm 生效时逐题或明确批量确认；拒绝建议保留原值。
4. 校验建议的答案键、题型、多空结构；模型给出不存在的选项不能通过。
5. 用户确认后，候选数据仍走正常导入校验与提交，不绕开 M6 的安全流程。

## 4. AI 补解析

1. 筛选缺解析题，明确本次处理题数与上限。
2. 根据 maxQuestions/refactorMaxChars 分批，保留题目身份；超长题单独提示，不能截去关键答案后当完整题处理。
3. 结果仅补缺省解析；用户已手动补写或题目版本变化时跳过并报告。
4. 取消阻止后续请求与迟到写入；已确认应用的结果保留，未确认结果可供之后查看。
5. 重试默认只处理失败/未完成项，不重复收费请求全部已成功题目。

## 5. 题库分析与知识点

1. 按题库隔离任务，选中多个库时分别显示面板与状态。
2. 将题库按输入长度限制分批，批内输出结构化知识点和关联题目身份。
3. 聚合时保留题目来源，不把相同名称但不同语义的知识点盲目合并。
4. 标记部分分析完成与失败批次，不用完整报告样式掩盖缺失。
5. 文本导出包含题库、模型、生成时间、覆盖题数与结果，不含 Key、鉴权头或私人端点凭据。

## 6. 持久化与恢复

优先复用已有缓存存储；独立 ai_cache.json 仅在体积或写入频率需要时引入。保存已完成批次、题目指纹和应用状态，避免重启后把同一建议应用两遍。

缓存与 state.json 不能假定跨文件原子更新：题目写入成功而缓存标记失败时，重试应通过指纹/目标值识别已应用结果。旧任务遇到 replace 或删除库应终止写回。

## 7. 验收矩阵

- [ ] 两个题库同 questionId，流式结果和应用范围互不干扰。
- [ ] 一批失败、后续取消、断网重试，计数与已应用结果正确。
- [ ] 取消后的迟到响应、重复点击、重复应用不会重复改题。
- [ ] 分析中改题/删库/导入 replace，旧结果不会覆盖新数据。
- [ ] 模型返回非法答案、缺字段、截断 JSON，只产生可查看错误或候选，不污染题库。
- [ ] 重启后已完成缓存可看，未完成任务提示中断；不宣称后台永久运行。
- [ ] 应用前后导出备份并核对目标题，原答案的恢复途径明确。

扩展 ai-stream 或新增最小 ai-batch 自检，使用本地模拟响应覆盖故障；真实服务只验证必要集成，不把高频付费请求当回归框架。

## 8. 出口
