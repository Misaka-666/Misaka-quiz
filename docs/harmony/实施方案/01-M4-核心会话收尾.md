## 2. 执行步骤

### 2.1 布局闭环

1. 检查 questionPane 的父 Column 与 Scroll：滚动区使用剩余空间，底部操作栏在可视区内。
2. 用真实容器或窗口宽度决定单/双栏，不能只在 `aboutToAppear` 读取显示器宽度。
3. 沿用 540vp 作为待验证题目双栏断点；断点基于可用宽度，不等同于某种折叠状态。
4. 折叠、展开、旋转时只更新布局，不重新启动会话或重置种子、答案、索引。
5. 打开软键盘、大字号、长题干、长选项、图片题时，提交与下一题仍可触达。
6. 检查 PanGesture 与纵向滚动、输入框选择文本的冲突，关闭滑动偏好后手势无效。

### 2.2 考试计时与交卷

现状：`ExamSessionCore.tick()` 按调用次数递减，页面 setInterval 驱动，不能把回调次数当作实际经过时间。

1. 使用现有 `PracticeHost.now` 注入时间；记录会话开始时间/截止时间，每次刷新由时间差推导剩余秒数，限制在有效范围内。
2. 页面定时器只触发刷新；恢复前台立即校准，到期则进入同一交卷入口。
3. 对设备时钟修改明确策略。优先核对本机 SDK 的单调时间能力；进程内可注入单调时钟，跨进程恢复单独使用持久化时间信息，不能混用不同时间原点。
4. 手动交卷、自动交卷、返回确认复用同一完成状态；重复请求不重复写记录或错题。
5. UI 导航发生在结果已生成之后；跳转失败时可重新进入同一成绩，而非再交卷一次。
6. 自检模拟跳过多个 tick、提前/到期提交、同一时刻重复提交，不使用真实等待十分钟的测试。

### 2.3 保存与恢复

1. Repository 检查 FileStore 写入结果；失败时保留内存数据并提示未保存，提供重试。
2. 退出保存顺序进度时，不能在写入失败后显示保存成功。
3. 区分文件不存在与读取/解析失败；异常文件保留供恢复，避免加载为空后覆盖旧文件。
4. 原子写入解决半写文件，不自动等于事务或所有故障均可恢复；按 09 文档增加旧文件保留与恢复测试。
5. 明确进程被杀策略：M4 必须保留已提交数据与已保存顺序进度；未完成练习/考试是否恢复需明确。若首版不恢复，重启提示本次会话已结束，不伪造完成记录。无缝恢复若列为必交，则另外持久化答案、种子、索引与截止信息并测试。

### 2.4 功能逐项验收

- [ ] 即时模式：六种作答形态、正确/错误颜色、答案与解析、下一题。
- [ ] 批量模式：10 题/组、最后不足一组、未答提示、补答、提交后不可重复计数。
- [ ] 背题模式：直接展示答案，不生成错误判分或意外推进复习状态。
- [ ] 顺序练习：从头/继续/指定起点、保存退出、完成推进、末尾回绕、题库变化后范围有效。
- [ ] 斩题：过滤生效、题库详情恢复、全部斩完有空态。
- [ ] 收藏：反复点击不重复，首页计数正确。
- [ ] 快速编辑：题干/答案/解析保存，旧判分失效，重新作答正确。
- [ ] 考试：两种组卷方式、题型库存不足提示、分值校验、跳题、手动/自动交卷。
- [ ] 字号与滑动偏好切换后生效。
- [ ] C1 导入 393 题，包含图片题以外的六种作答形态补充样例，不能只靠 C1 覆盖填空/简答。

## 3. 最小自检与设备证据

扩展现有 `test/harmony-parser-regression/session-core.mjs`，不新增测试框架。计时、重复提交、保存失败传播分别保留一个能失败的检查；平台文件失败在设备上验证。

PhoneAPI26：单栏、sheet、键盘、大字号。WideFoldM4：两种形态及作答中切换，记录实际 vp 尺寸和截图，不根据物理像素猜断点。
