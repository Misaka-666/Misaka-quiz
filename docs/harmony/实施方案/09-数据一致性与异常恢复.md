# 跨阶段：数据一致性与异常恢复

文档版本：1.0 · 适用 M4–M9 · [返回索引](README.md)

本文件列出建议采用的项目规则。与 Android 既有行为有差异时，先核对并记录最终选择；不要把建议误标为当前实现。

## 1. 身份与引用

| 数据 | 建议规则 |
| --- | --- |
| 题目身份 | 使用 bankId + questionId；会话若允许重复题另带会话条目键 |
| 收藏/错题 | 按来源身份去重，计数/筛选/练习统一同一规则 |
| 学习记录 | 保存当时题目、正确答案、解析、用户答案与判分快照 |
| 顺序进度 | 键仍兼容 BANK:<id>；删除/重排/导入后检查索引有效 |
| 斩题 | 保持现有 questionKeyOf 语义，编辑与重映射时明确是否保留 |
| AI 缓存 | 来源身份 + 内容指纹 + 模型/端点标识 + 提示词版本 |
| 图片 | 公共相对资产路径；引用者包括历史快照，不能只查当前题库 |

快照应与后续编辑解耦；仅把同一可变对象赋给记录不一定构成快照。实现时核对克隆与解析路径，优先复用现有转换函数。

## 2. 变更语义

- 编辑题目：更新当前题源及需要跟随的错题/收藏；旧会话判分失效；历史记录不追溯修改。
- 删除题目/题库：建议清理实时收藏、错题、斩题与顺序进度，保留历史记录快照；若 Android 采用其他规则，写明差异后再实施。
- 删除历史记录：只删除该记录，不改变题目当前掌握状态，除非基准明确具有回算语义。
- 手动掌握/取消：状态、连续正确次数、复习等级和排期必须一致，不能只改显示标签。
- 批量导入 replace：使受影响会话和 AI 任务失效，禁止旧回调写回新状态。
- 清空全部：先阻止异步写入，再清数据；清理失败可重试，不能显示完全清空成功。

## 3. 时间规则

考试剩余时间按实际时间差推导，定时回调仅负责刷新。区分进程内单调计时和持久化后的墙钟时间；设备改时行为必须明确。

智能复习按本地自然日定义到期边界。当前代码通过日初加固定毫秒数推进，若支持跨时区/夏令时场景，应改用日历日期运算并加入测试；不要默认为一天永远等于 24 小时。

所有时间相关纯逻辑接受可注入时间，测试覆盖边界而不依赖真实等待。

## 4. 存储与失败

1. 区分不存在、不可读、非法 JSON、模型不兼容，不统一当空数据。
2. 临时写入成功且关闭后才替换正式文件；写入失败向调用者传播。
3. 保留可恢复旧状态或明确恢复副本，异常启动不自动覆盖原文件。
4. 全量状态保存需串行化实际提交，避免后发旧快照覆盖新状态；优先复用现有同步流程，不无故加并发。
5. state.json、preferences、资产目录不是单一原子事务；跨资源导入使用 M6 的候选状态与恢复流程。
6. 启动清理临时文件需辨别有效恢复数据，不能见 tmp 就删。

## 5. 输入与敏感信息

- 文件、备份 JSON、data URI、模型响应均属于需要校验的输入。
- 校验类型、大小、路径、引用与答案结构，再进入正式模型。
- 外部文本只当数据展示，不执行其中的指令或脚本。
- Key、鉴权头不写日志、备份和测试资产；调试截图避免带出敏感表单内容。
- 测试资产使用合成或脱敏数据，记录来源及许可情况。

## 6. 规模与性能

首版保留 JSON 存储，不预先引入数据库。使用 C1、约千题、约万题及含图片/历史记录的数据观察导入、保存、搜索和列表表现；记录设备、数据字节数、耗时和可感知卡顿。

若全量同步序列化/写入阻塞 UI，再有针对性调整写入频率或执行位置。延迟保存必须保留退出/切后台的提交策略，不能以性能优化牺牲数据可靠性。

## 7. 必须保留的回归情形

- 同 ID 不同库、同名不同库、重复导入、历史快照后改题。
- 删除题库后查看记录图片，资产未误删。
- 写入失败后重试、损坏文件启动、导入各提交阶段中断。
- 复习跨日、考试后台超时、交卷重复、AI 迟到回调。

规则最终确定后，将对应例子转成现有 Node 自检或设备检查；不只停留在文档口头约定。
